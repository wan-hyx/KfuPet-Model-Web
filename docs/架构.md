# 架构

## 1. 技术选型

| 部分 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite | |
| UI / 样式 | Naive UI + Tailwind CSS | |
| 后端 | NestJS + TypeScript | |
| ORM | Prisma | |
| 数据库 | PostgreSQL 16 | |
| 认证 | JWT + Passport + bcrypt | 无状态，便于客户端接入 |
| 校验 | class-validator + class-transformer | NestJS 标准 |
| 文件存储 | 本地磁盘（经 `storage` 抽象层） | 后续可替换为 MinIO / OSS / R2 |

| 反向代理 | Nginx | TLS、静态文件、`/api` 反代、`X-Accel-Redirect` |

| 服务器 | 单台香港 VPS（Ubuntu 24） | 三网直连线路，免备案 |

## 2. 部署拓扑

```text
公网
 └── Nginx（容器）          TLS · 静态文件 · /api 反代 · /files 内部直出
      ├── NestJS（容器）     业务接口 · 上传 · 审核
      │    └── PostgreSQL（容器）
      └── uploads 卷         模型包 / 封面（挂载给 Nginx 只读直出）

宝塔面板只做运维：防火墙 · 监控 · 计划任务（不托管 Nginx、数据库）
```

## 3. 文件存储与抽象层

业务代码**不直接读写磁盘**，统一走 `storage` 接口：

```ts
interface Storage {
  put(key: string, data: Buffer): Promise<string>  // 返回 sha256
  get(key: string): Promise<Buffer>
  delete(key: string): Promise<void>
  urls(key: string): Promise<string[]>             // 本地路径 / 镜像列表 / 对象存储
}
```

- 默认实现：本地磁盘 `backend/uploads/`
- 意义：将来换 MinIO / OSS / R2，只改一个实现，业务代码零改动

## 4. 大文件下载

- 下载接口**不返回文件流**，只返回响应头 `X-Accel-Redirect: /files/<key>`
- 由 Nginx 直接发文件，不占用 Node 的内存与事件循环
- 这是保住服务器带宽、撑住并发的关键

## 5. 分发演进（三阶段）

1. **单机**：中心服务器 + 本地磁盘
2. **镜像**：贡献者跑 Go agent（注册 / 心跳 / rsync 同步），一条命令接入
3. **调度**：客户端从主 API 取得「含 `sha256` 的清单」→ 校验 → 从最快镜像下载

不做 P2P / IPFS。

## 6. 完整性校验

- 每个模型包在 `manifest.json` 里带 `sha256`
- 客户端下载后**本地校验**，不匹配直接拒绝并上报
- 贡献节点的服务器不受我们控制，这是唯一的防线

## 7. 客户端接入

Windows / Android KfuPet 通过同一套 `/api` 获取模型列表、详情、更新日志与下载地址，无需浏览器。
